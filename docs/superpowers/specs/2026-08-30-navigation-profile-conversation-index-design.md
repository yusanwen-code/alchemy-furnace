# 导航、个人头像与会话目录重构设计

**日期：** 2026-08-30  
**状态：** 已完成产品设计确认，待实施计划  
**范围：** 顶部导航、设置中的用户头像、论道会话身份契约、会话目录、围炉论道主题

## 背景

当前界面存在五类相关问题：

1. “融合”是独立顶级导航，但产品希望将其归入“金丹阁”。
2. “金丹阁”和“道人府”的下拉菜单包含尚未形成独立信息架构的入口，增加了导航噪声。
3. 用户档案接口已有 `avatar` 字段，但“我的简介”表单无法设置头像。
4. 单聊会话响应只携带 `agent_id`。前端必须等待另一份道人列表，再通过 ID 查找名称；数据未到或查找失败时会展示通用“道人/选择道人”，而不是真实道人名称。
5. 所有单聊和群聊混在一个平铺会话列表中。单聊缺少按道人聚合的层级，群聊也缺少易识别、可维护的主题名称。

## 目标

- 将“融合金丹”作为“金丹阁”的子入口，不改变现有融合业务路由。
- 精简“金丹阁”和“道人府”的顶部导航结构，同时保留对应页面内的现有业务能力。
- 在“我的简介”中支持配置并预览用户头像。
- 让会话响应直接携带稳定的单聊道人身份数据，消除前端跨列表推断名称造成的错误展示。
- 将会话目录拆分为“对谈”和“围炉论道”，并为单聊建立“道人 → 会话”的父子层级。
- 支持围炉论道创建时设置主题、创建后重命名，以及未设置时自动命名。

## 非目标

- 不改变 `/pills` 和 `/fusion` 路由，也不合并两个页面的业务代码。
- 不删除道人列表页里的创建、搜索、筛选、详情编辑或服丹能力。
- 不新增头像文件存储、裁剪或上传服务。
- 不新增单聊手动主题输入；单聊继续使用现有自动命名。
- 不建立专门面向树形 UI 的会话目录接口；继续复用现有会话列表接口。
- 不修改消息内容、SSE 协议、群成员发言顺序或只读会话规则。

## 方案选择

采用“补强现有会话契约”的方案：会话响应直接携带单聊道人名称、头像和状态；群聊创建请求原子接收可选主题；前端基于扁平会话数据构造展示分组。

未采用的方案：

- 仅前端通过道人列表补全身份：仍有加载竞态，深链或道人列表失败时无法可靠展示。
- 新增树形会话目录接口：会把后端契约与当前 UI 层级过度绑定，当前规模下没有必要。

## 导航设计

### 金丹阁

顶部删除独立“融合”导航项。“金丹阁”下拉只保留：

- “全部金丹” → `/pills`
- “融合金丹” → `/fusion`

访问 `/pills`、金丹详情或 `/fusion` 时，顶部“金丹阁”均应显示为激活状态。移动端菜单使用相同信息架构，不再显示独立“融合”。

### 道人府

“道人府”下拉只保留“道人列表” → `/agents`。道人列表页内部继续提供创建道人、搜索、状态筛选、详情编辑和服丹等能力。

## 用户头像设计

“设置 → 我的简介”在显示名和个人简介之外增加头像编辑区：

- 使用统一 `EntityAvatar` 展示当前预览。
- 接受完整 `http://`、`https://` URL，或受支持的 `data:image/...;base64` 数据 URI。
- 输入为空表示清除自定义头像，界面回退到显示名首字头像。
- 输入过程中更新预览；加载失败时必须回退，不显示破图。
- 保存时将 `avatar` 与 `display_name`、`bio` 一起提交。

用户头像校验应复用道人头像的规则和错误文案：

- URL 必须是完整 HTTP/HTTPS URL，不允许用户名或密码。
- data URI 仅支持 PNG、JPEG、WebP、GIF 的 Base64 数据。
- 普通 URL 最长 2048 个字符；data URI 最长 1,500,000 个字符。

现有 `UserProfile.Avatar` 数据库列和请求绑定上限只有 500 字符，实施时必须同步扩大为文本列及上述契约上限，不能只改前端。

## 会话数据契约

### 响应

现有 `ChatSession` 响应增加单聊身份字段：

- `agent_name: string`
- `agent_avatar: string`
- 继续使用现有 `agent_status: string`

这些字段由服务端从会话预加载的 `DaoAgent` 关联生成。单聊列表、单聊深链和创建单聊的响应必须保持一致。群聊的上述字段为空，成员身份继续由 `members` 提供。

前端不再把全局道人列表作为单聊名称、头像的主要来源。道人列表只用于创建新会话、成员管理和必要的兼容兜底。

### 创建群聊

创建会话请求的群聊分支接受可选 `title`：

- 去除首尾空格后为空：作为未命名群聊创建，保留首次问答自动命名。
- 非空：最多 200 个 Unicode 字符，并与成员关系在同一创建操作中保存。
- 超长：返回稳定的参数错误，不创建会话或成员。

单聊创建仍忽略客户端主题，避免扩大本次产品范围。

### 重命名

继续使用 `PUT /api/v1/chat/sessions/:uuid`：

- 只在围炉论道界面提供入口。
- 标题去除首尾空格后不得为空，最多 200 个 Unicode 字符。
- 成功后同时更新当前会话和会话列表中的对应项。
- 失败时保留编辑值并展示错误，用户可以继续修改或重试。

## 会话目录设计

桌面侧栏与移动端 Sheet 共用一个会话目录组件，顶部提供两个 Tab。

### 对谈

- 仅展示 `type` 为 `single` 或历史缺省类型的会话。
- 使用 `agent_id` 分组，父级展示 `agent_avatar` 和 `agent_name`。
- 父级下展示该道人的全部单聊会话标题。
- 道人分组按组内最新 `updated_at` 倒序；组内会话也按 `updated_at` 倒序。
- 当前会话所在父级自动展开；其他父级允许展开或收起。
- 道人停用后，历史会话继续展示在原道人名下，打开后沿用现有只读提示。
- 空状态文案为“暂无对谈”。

### 围炉论道

- 仅展示 `type === "group"` 的会话。
- 使用平铺列表，主标题显示群聊主题。
- 辅助信息展示成员头像、成员人数和最近更新时间。
- 未命名群聊在自动命名前使用现有“新群聊/围炉论道”兜底文案。
- 空状态文案为“暂无围炉论道”。

### Tab 状态

- 打开具体会话时，自动选中该会话所属 Tab。
- 在大厅且没有当前会话时，默认选择“对谈”。
- 用户手动切换 Tab 后，只改变目录筛选，不创建、打开或删除会话。

## 聊天页头

- 单聊页头的名称和头像直接读取当前会话的 `agent_name`、`agent_avatar`。
- 群聊页头显示主题和成员数，并提供重命名入口。
- 桌面侧栏、移动端 Sheet、聊天页头必须共用相同的会话身份字段和标题规则。

## 状态与错误处理

- 会话目录加载失败与道人列表加载失败继续独立展示；道人列表失败不得使已有单聊名称退化为通用“道人”。
- 创建围炉论道失败时保留主题与成员选择，并显示后端错误。
- 重命名失败时不乐观覆盖本地标题；保留输入供重试。
- 头像值非法时禁止提交并显示字段错误；头像加载失败只影响预览，使用首字回退。
- 历史数据中缺少新身份字段时，前端可临时用已加载道人列表匹配；仍找不到时使用明确的“未知道人”，不得显示操作提示“选择道人”。

## 国际化与可访问性

- `frontend/messages/zh-CN.json` 与 `frontend/messages/en.json` 同步增加或调整导航、头像、会话 Tab、空状态、主题创建和重命名文案。
- Tab 使用可识别的 `tablist`、`tab` 和选中状态语义。
- 道人父级展开按钮暴露 `aria-expanded`；头像输入、重命名输入和错误提示均有可关联标签。
- 键盘可以切换 Tab、展开道人分组、进入会话、保存或取消重命名。

## 测试策略

### Go

- 会话 DTO：单聊列表、直接读取和创建响应均包含正确的道人 UUID、名称、头像、状态。
- 群聊创建：显式主题原子保存；空主题进入自动命名；超长主题零落库。
- 重命名：空白、超长和正常标题的边界一致。
- 用户头像：合法 URL、合法 data URI、非法协议、非法 data URI、长度边界和清空行为。

### 前端

- 导航：独立融合项消失；金丹阁只有两个子项；道人府只有道人列表；`/fusion` 激活金丹阁。
- 个人资料：初值回填、头像预览、清空、非法值、保存载荷和图片失败回退。
- 会话目录：双 Tab 筛选、默认 Tab、按道人分组、排序、展开状态、群聊主题及空状态。
- 单聊身份：道人列表未加载或失败时仍显示会话返回的真实名称与头像。
- 群聊主题：创建时提交、未填写自动命名、创建失败保留输入、重命名成功和失败。
- 桌面与移动端复用相同目录行为。

### 回归

- 运行 `cd backend/go && go test ./...`。
- 运行前端目标测试与完整测试套件。
- 运行 `cd frontend && pnpm lint`。
- 运行 `cd frontend && pnpm build`。
- 在 Web 开发模式与 Wails 桌面壳中人工检查导航、头像、单聊深链、双 Tab、群主题创建与重命名。

## 验收标准

1. 顶栏不再有独立“融合”；金丹阁只有“全部金丹”和“融合金丹”，道人府只有“道人列表”。
2. `/fusion` 仍可直接访问且金丹阁保持激活。
3. “我的简介”可设置、预览、保存和清除头像；所有头像位置刷新后使用新值。
4. 单聊列表与页头始终显示会话所属道人的真实名称和头像，不依赖道人列表请求成功。
5. “对谈”Tab 以道人为父级显示多个会话；“围炉论道”Tab 只显示群聊主题。
6. 围炉论道可在创建时设置主题，也可创建后重命名；未填写时继续自动命名。
7. 中文和英文文案同步，桌面与移动端行为一致。
8. Go 测试、前端测试、Lint 和生产构建全部通过。
