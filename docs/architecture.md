## 服务说明

### 1. 前端 React SPA

- **技术栈**: React 18 + TypeScript + Tailwind CSS + shadcn/ui
- **路由**: HashRouter，兼容静态部署
- **特性**: 响应式设计，一套代码兼容 Web 端和 H5 移动端
- **页面**: 首页、金丹阁、道人府、炼丹室、设置

### 2. Go API 网关

- **技术栈**: Go 1.21 + Gin + GORM + WebSocket
- **职责**:
  - 接收前端 HTTP / WebSocket 请求
  - 业务数据管理（PostgreSQL）
  - 文件上传处理
  - 调用 Python RAG 引擎
  - 流式对话转发
- **架构模式**: 分层架构（handler → service → dao）

### 3. Python RAG 引擎

- **技术栈**: FastAPI + LangChain + Qdrant + OpenAI
- **职责**:
  - 文档解析（doc/xlsx/md/txt/pdf/audio/video）
  - 文本切分和向量化
  - 向量存储和相似度搜索
  - LLM 对话（支持流式）
  - 音频转录和视频字幕提取

### 4. 数据存储

| 存储 | 用途 | 数据 |
|------|------|------|
| PostgreSQL | 业务数据 | 金丹、丹方、道人、会话、消息 |
| Qdrant | 向量数据 | 文本块向量 + 元数据 |
| 文件系统 | 原始文件 | 上传的文档、音频、视频 |

## 核心流程

### 炼丹流程（RAG Pipeline）

```
用户上传文件
    │
    ▼
Go API 接收 → 保存文件系统 → 记录数据库(elixir_recipes)
    │
    ▼ (异步调用 Python RAG)
Python RAG:
  1. 文档提取 → 原始文本
  2. 文本切分 → chunks
  3. Embedding → 向量
  4. Qdrant 入库
    │
    ▼
更新金丹状态 → refined
```

### 对话流程

```
用户发送消息
    │
    ▼ WebSocket
Go API:
  1. 保存用户消息
  2. 查询会话关联的 Agent
  3. 获取 Agent 绑定的 pill_ids
  4. 调用 Python RAG search
    │
    ▼ HTTP
Python RAG:
  1. Embedding query
  2. Qdrant 搜索 (filter by pill_ids)
  3. 返回相关 chunks
    │
    ▼
Go API:
  4. 构建 Prompt (system + context + query)
  5. 调用 LLM API (SSE 流式)
  6. 流式转发给 WebSocket 客户端
  7. 保存 AI 回复
```

## 技术选型理由

| 技术 | 选型理由 |
|------|---------|
| React + TS | 组件化开发，类型安全，生态丰富 |
| Go | 高并发，编译型，资源占用低，适合 API 网关 |
| Python | AI/ML 生态成熟，LangChain 完善 |
| Qdrant | 轻量高效，Docker 一键启动，API 简洁 |
| PostgreSQL | 成熟稳定，JSON 支持，GORM 兼容好 |
| Nginx | 高性能静态文件服务，反向代理 |
| Docker Compose | 一键编排，环境隔离，易于部署 |
